## What was built
- **Tools** (specialist-only, optional eligible tools of `market_analysis`, granted by main through `requested_tools`; a separate toolset each): `marketplace_locate`, `marketplace_search`, `marketplace_item`, `marketplace_photo` (`app/research.py`). No arbitrary HTTP/URL tool, no credential argument; photos come only from URLs a provider response of this run recorded, on an allow-listed Facebook CDN host (`.fbcdn.net`, `.facebook.com`, `.fbsbx.com`), fetched without any API credential and with TLS verification.
- **Reuse:** response checks, normalisation, field-level merge, TLS context, HTTP and image decoding are imported by path from `scripts/marketplace_check.py`. Its CLI, its 20-request ledger (19/20) and its evidence/photo files are never read or written by the app tools, and the script is unchanged.
- **Runs and evidence:** a research run is opened lazily, at most once per (agent, manual request), from backend-supplied identity (`ECOM_AGENT_ID`, `turn_state.request_id` set by the worker from the server's request id); the model cannot name, reuse or open runs. SQLite (additive): `research_runs`, `research_calls` (kind, params, status, outcome, HTTP status, credits, ms), `research_listings` (normalised records with URLs, retrieval times, descriptions, photo references), `research_photos` (downloaded-file sha256/size/dimensions/host), `research_allowance`. Seller IDs are pseudonymised in draft evidence; signed photo URLs are never returned to the model, the read APIs or drafts.
- **Allowance:** finite, persisted per scope (`ECOM_RESEARCH_SCOPE`) plus per-run caps. An attempt is reserved in one atomic `BEGIN IMMEDIATE` transaction BEFORE sending, failures included; concurrent processes serialise on it. An existing scope's caps are never re-sized from configuration, tools cannot carry budget/run/URL arguments, and one request cannot open a second run. Identical successful requests are answered from the run's store (not re-sent, not re-counted); an identical request whose earlier outcome is unknown (crash, timeout, dropped connection) is refused, never replayed.
- **Draft path:** `save_listing_draft` now takes its evidence from the request's own run (`evidence_source` live_research) or from the recorded sample (`recorded_sample`); an agent holding both must say which, and a live draft can only cite listings that this run retrieved. Live photos are inspected with `inspect_image` (run photo directory first; the old diagnostic photo cache is invisible inside a run) and carry kind `live_listing_photo`, the hash recorded at download, `delivery` status and `counts_as_verified_evidence`. All ticket-04 checks (source-hash, price/currency, vision status, durable supporting evidence) apply unchanged. `listing_drafts` gained `evidence_source` and `research_run_id` (additive; old rows read as `recorded_sample`).
- **Catalogue context:** a catalogue is supplied only to the company it belongs to: `catalogue_company_mismatch`, `company_missing` and `catalogue_missing` are explicit errors; the merchant's market location (`merchant.market.location_query`) is catalogue data, so another merchant/product/location needs no code edit.
- **Surfaces:** Activity labels for the four tools; `GET /api/research/runs[?agent_id=]`, `GET /api/research/runs/<id>`, `GET /api/research/allowance`; drafts read API shows `evidence_source` and `research_run_id`. Specialist SOUL states the connected research and its limits only when the tools are granted. Research turns get a 600 s timeout and 14 agent iterations (+1 summary request, so at most 15 model requests per request); profiles disable Hermes' automatic skill-review nudge, which would add an uncounted background model request after a 10+ iteration turn.

## What was not captured (honest gaps)

The saved draft exists only in that deleted copy, as in ticket 04; the real runtime contains no live draft.

## Limitations
- Single product, single market (Dallas), one request, development provider; the specialist's behaviour is one sample, not a benchmark. It spent one API attempt on a redundant second location lookup and used a model request to look at the catalogue illustration.
- Vision status is Hermes' gate for the provider/model at inspection time; Nebius/NVIDIA behaviour with tools and images is unverified.
- Relevance judgement, price and claim guards remain the specialist's and keyword heuristics respectively; asking prices are not sales or demand.
- Search results are provider-ranked; two of the three cited comparables are from Hudson Oaks and Wylie, i.e. outside Dallas proper (the radius is the provider's); seller identity is pseudonymous and not assumed to be a company.
- The scope allowance is operator configuration (environment at first use); there is no UI or CLI to raise it, by design. Default real-runtime caps (60 API / 20 photos per scope; 12 / 4 per run) were chosen from the 19-request sample and are not tuned.
- A provider outcome that is unknown stays unknown: the run shows it and the identical request is refused; the user must start a new request to try again.
