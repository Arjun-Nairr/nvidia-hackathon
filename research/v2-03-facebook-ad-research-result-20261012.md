## 2. Tools (all specialist-only, social_media only, one toolset each)
| Tool | Model inputs | Backend call | Returns |
|---|---|---|---|
| `fb_ads_find_advertiser` | `query` | `search/companies` | `advertiser_no`, name, category, likes, verification (no page id) |
| `fb_ads_search` | exactly one of `query` / `advertiser_no`; `status` ACTIVE/INACTIVE/ALL; `order` default/most_recent; `next_page` | `search/ads` (keyword_unordered) or `company/ads` (pageId held by the backend) | one entry per distinct `ad_archive_id`: `ad_no`, `source_ad_id`, public `source_url`, advertiser, text snippet, image/card counts, `campaign` grouping, `reach` state, plus `reach_gate`; skipped rows disclosed |
| `fb_ad_detail` | `ad_no` | `ad` (`id` = the recorded archive id) | text, cards, image references (`image_no`), landing domain, campaign, raw reach fields with meaning, available metrics |
| `fb_ad_image` | `ad_no`, `image_no` | CDN download of that image's recorded reference | registered `image_id` (`ad-<ad id>-<n>`), sha256, size, serving host |
| `save_ad_research` | `summary`, `selection_basis`, `references[]`, `blocker?`, `limitations?` | none (SQLite) | `package_id`, status complete/partial/blocked, missing, reach gate |
| `read_ad_research` | `package_id?` | none (SQLite) | saved package summaries / one package |

Fixed by the backend and not model arguments: country `US`, media type (`IMAGE_AND_MEME` by default, `ECOM_ADS_MEDIA_TYPE`), credentials, URLs, page ids, cursors, run identity, caps. Unknown arguments (`country`, `url`, `page_id`, `cursor`, `max_requests`, `run_id`, `reset_allowance`, `api_key`, ...) return `invalid_argument` and send nothing. Image ads only: a row whose format is VIDEO is excluded and counted; a detail that reveals a video ad blocks downloads for it.

## 3. Budget, accounting and replay rules
- **Allowance:** per manual request (one run per agent+request) `ECOM_ADS_RUN_API_MAX` default **8** scraper attempts and `ECOM_ADS_RUN_IMAGE_MAX` default **4** image downloads, inside a per-scope total (`ECOM_ADS_SCOPE`, `ECOM_ADS_API_MAX` default 40, `ECOM_ADS_IMAGE_MAX` default 20) fixed the first time a scope is used. These are operator settings read by the backend; no tool argument can set, raise or reset them, and a larger value in the environment later does not re-size an existing scope.
- **Reservation:** one `BEGIN IMMEDIATE` transaction both counts the attempt and records it as `reserved` BEFORE the request is sent. Failures (HTTP error, malformed body, redirect refusal, identity mismatch, local save failure) stay counted. A dropped connection or crash leaves the attempt `reserved`/`network_error`: the identical request is refused (`uncertain_previous_attempt`), never replayed.
- **Cache:** an identical successful search/advertiser/detail/image call in the same run is answered from the run's store with no request and no count.
- **No hidden retries:** one `urllib` request per reserved attempt; API redirects are not followed (the credential cannot be forwarded); CDN redirects only to allow-listed hosts (<= 3 hops, no HTTPS downgrade); no credential on downloads; TLS verification on.
- **Local storage failure:** a result that arrived but could not be saved is `ok_unsaved`: reported as sent+counted+not saved, and the identical request is refused (`storage_error`) instead of re-sent. Same for an image that could not be written.
- **Cannot be replenished by:** a new request id in the same scope, an app restart, parallel calls (4 processes racing for 10 attempts sent exactly 10), a model-supplied id or a larger environment value.

## 4. What is persisted (SQLite, `runtime/app.db`; image bytes under `runtime/ad_research/<run_id>/images/`)
`ad_runs` (agent, company id/name snapshot, conversation, request, message, scope, caps, country, media type), `ad_calls` (kind, endpoint, params, status, outcome, HTTP status, provider-reported credits, ms, error), `ad_advertisers`, `ad_records` (one row per distinct ad: ids, public link, advertiser, text, cards, image references incl. signed URLs (backend-only), campaign id/count, raw reach/impression/spend fields, retrieval times, identity check), `ad_images` (managed id, ad, image_no, source field, sha256, bytes, size, host, fetched_at), `ad_packages` (identity, status, summary, selection basis, blocker, reach-gate snapshot, cited ads, references with observations/lineage, every ad considered, call accounting). Nothing large goes into specialist memory. `collation_id`/`collation_count` are stored as campaign grouping beside, never instead of, each `ad_archive_id`; cards are variants of one ad (`card_count`, never extra ads).

## 5. Reach gate (no proxy, no guess)
| Provider field | State | Why |
|---|---|---|
| numeric `aaa_info.eu_total_reach` (detail) | `reported`, metric `eu_total_reach`, geography **EU**, period not stated | Documented by Meta, EU-delivered ads only; labelled "NOT US reach" |
| `reach_estimate` / `reachEstimate`, or a non-numeric `eu_total_reach` | `ambiguous` | Not defined by ScrapeCreators; raw value kept in `provider_value`, never compared or ranked |
| nothing / null | `unavailable` | Unknown, not zero |
| `impressions_with_index` (index -1 = null), `spend` | stored as `other_metrics`, labelled "NOT reach" | Never substituted for reach |
Gate (computed from every ad recorded in the run): `enabled` only when >= 2 ads carry a reported value of the same metric and geography; otherwise `disabled_reach_unavailable`, `disabled_reach_ambiguous`, `disabled_single_value` or `disabled_incompatible_metrics`. Absence disables reach-based ranking only: search, inspection and the package continue, and the package states "reach ranking was unavailable". `save_ad_research` refuses `selection_basis: reach_ranked` unless the gate is enabled and every cited ad carries the reported value, and refuses sales/effectiveness/popularity claims (heuristic regexes; `unsupported_claim`).

## 6. Actual-image lineage
`fb_ad_image` registers the bytes (sha256 at download) -> `inspect_image` (existing path; the backend prepares the pixels, the existing Hermes gate decides `image_part_sent` / `text_fallback` / `unknown`, logged with the file's sha256 as kind `live_ad_image`) -> `save_ad_research` accepts a reference only for an image of THAT ad, registered in THIS run and inspected in THIS request with the same bytes. A reference whose delivery is not `image_part_sent` is saved but the package is `partial` ("model text only, not verified visual evidence"). The test checks the model REQUEST itself: the scripted model endpoint decoded each image part and its size and mean colour equal the registered ad images' (`B8`), independent of what the scripted model wrote.

## 7. How an existing social specialist obtains the tools (no silent widening)
Grants are read from the stored registry row per turn and are never rewritten by code; `core.sync_profiles()` rewrites only provider/model config; a specialist's SOUL and skills are written once at creation (test `B16`: grants and SOUL bytes unchanged after all scenarios and restarts). A social specialist created before V2-03 therefore keeps exactly its old grants, its old SOUL (which says ad research is not connected) and its old Hermes session. To get the tools: ask main to create a NEW social specialist (a different name) with `requested_tools` listing the six `fb_*`/package tools (+ `inspect_image`, `read_catalogue`); `create_agent`'s description now lists them. The old specialist stays untouched. I did not add an in-place grant-upgrade script: its saved SOUL and session system prompt would contradict the new tools. The real runtime currently has no social specialist.

## 10. Audit of the introduced code (own scoped pass; Codex runs the ticket's two-reviewer pass separately)
- Fixed: a first draft allowed `save_ad_research` before any attempt (now refused unless nothing prevented trying, so an exhausted allowance still ends in an honest blocked package); a detail that revealed a VIDEO ad had cleared the exclusion; image bytes were served with the provider's `Content-Type` (now derived from what the file decoded as); duplicate advertiser rows could be numbered twice; list view repeated long explanatory text per ad (compacted; the meaning is in detail and the gate); package retrieval/inspection times were epoch floats mixed with ISO strings.
- Checked, no change: signed CDN URLs and the key appear in no tool result, API response, package or log line written by this module; the stored `error` strings are not returned; parallel `save_ad_research` is serialised by a UNIQUE run id; `ad_no` allocation is inside the same immediate transaction as the insert.
- Test-harness findings, not product defects: the worker truncates stored tool output at 3,000 characters (existing), so the test parses the list view; a scripted run with `first=relevant` legitimately spent a download, so the allowance scenario uses `first=irrelevant`.

2. Whether any US ad carries a non-null reach field; which of `reach_estimate` / `aaa_info.eu_total_reach` appears and with what meaning. Until observed, the expected live state is "reach ranking unavailable".
3. Whether a failed provider call is charged (undocumented) - failures are counted against the allowance either way; whether signed image URLs expire before download; real latency (60 s API / 30 s image timeouts are guesses).
4. The default list order is the provider's impressions order (`sort_by` default is `total_impressions`): used only as an order, never as reach. The docs say a very long pagination needs POST; the 8-attempt cap makes that unlikely and POST is not implemented.
5. Real model behaviour (query choice, relevance judgement, observation quality, honest blockers), Nebius/NVIDIA tool and image-in-tool-result behaviour, and the Hermes vision gate for any model other than the one proven in V1.
6. Gemini generation, the merchant sample and the flyer flow (tickets 04-06) are untouched.
